# スキル編集ガイド

## 基本方針

スキルは、別のCodexが後で読んでも迷わず使える最小限の手順書として書く。

- 汎用ルールはスキルに書く。
- プロジェクト固有の用語、ファイル名、運用ルールは、可能ならリポジトリ内の文書を参照する指示にする。
- 例は理解を助けるために使い、特定プロジェクトにしか通用しない例を中心にしない。
- スキル本文に情報を複製しすぎない。元文書が更新されたときに古くなる情報は参照に寄せる。

## 修正前に確認すること

1. 対象スキルの `SKILL.md` を先頭から最後まで読む。
2. `agents/openai.yaml` がある場合は、表示名、短い説明、default prompt が `SKILL.md` と矛盾していないか確認する。
3. `references/`、`scripts/`、`assets/` がある場合は、今回の修正に関係するものだけ確認する。
4. ユーザーの依頼が「スキル本文の方針追加」なのか、「プロジェクト固有の知識追加」なのかを分ける。
5. 既存の未追跡ファイルや変更済みファイルがある場合は、無関係な変更を巻き戻さない。

## 書くべき内容

- そのスキルをいつ使うかが分かる `description`
- 実行順序が必要な作業では、短い手順
- 判断が必要な作業では、優先順位や判断基準
- ユーザー指定と既存文書のどちらを優先するか
- 適用する箇所と、適用しない箇所
- 検証方法や確認観点

## 避ける内容

- 特定リポジトリでしか意味を持たないファイル名や用語を、汎用スキルの中核ルールとして固定すること
- 参照元文書と同じ用語定義を大量に複製すること
- README、CHANGELOG、補助メモなど、スキル実行に不要なファイルを増やすこと
- ユーザーが求めていないスクリプト、参照ファイル、資産ディレクトリを追加すること
- 例外条件を本文の奥に隠すこと

## 参照資料のスコープ

参照元に含まれる内容をそのまま取り込むのではなく、作成・修正するSkillの利用者が実行する作業に必要な範囲だけを残す。

- ユーザーが不要と指定した外部URL、埋め込み、画像参照、インストール手順、GUI操作は削除する
- コーディングエージェントの編集・検証に不要な、個人環境のセットアップ手順や操作メモは残さない
- ユーザーが参照元の完全収録を明示した場合は完全性を優先し、通常の可搬性方針から外れる範囲を明記する
- 参照元の内容を要約・選別する場合は、技術的な判断に必要なコード例、設定例、制約、検証手順を優先する

## 参照資料の健全性

参照ファイルを追加または更新した場合は、内容の正しさだけでなく、その参照が対象リポジトリで利用可能か確認する。

- 相対リンク、画像パス、添付ファイルを確認し、存在しない参照を残さない
- 外部URLを残す場合は、ユーザーが外部参照を許可または必要としたことを確認する
- ユーザー名、学生番号、絶対パス、ローカルフォント名、特定プロジェクト名などは、必要がなければ一般化する
- コード例に実行環境依存の値を残す場合は、その依存条件と適用範囲を明記する
- 大きい参照資料は、Skill本体から必要な場面を示して参照させる。常に全体を読む前提にしない

## 可搬性の保ち方

プロジェクト固有の文書を直接名指しする代わりに、次のように書く。

```markdown
作業対象リポジトリまたは対象文書に、用語集、略語一覧、表記規則、スタイルガイドがある場合は、文書修正前に参照する。
```

特定ファイル名を挙げるのは、そのスキルが特定プロジェクト専用である場合、またはユーザーが明示的にそのファイルを基準にするよう求めた場合に限る。

## メタデータ

`SKILL.md` のfrontmatterは `name` と `description` だけにする。

- `name`: 小文字、数字、ハイフンだけを使う。
- `description`: 何をするスキルか、どのような依頼で使うかを簡潔に書く。

`agents/openai.yaml` を置く場合は、UI向けの値が本文と一致しているか確認する。

- `display_name`: 人が見て分かる短い名前
- `short_description`: 25〜64文字程度の短い説明
- `default_prompt`: `$skill-name` を含む短い起動文

## 検証

修正後は最低限、以下を確認する。

- `SKILL.md` にTODOやテンプレート文が残っていない。
- frontmatterの `name` とディレクトリ名が一致している。
- `description` がスキルの用途と発動条件を説明している。
- `agents/openai.yaml` がある場合、`default_prompt` に `$skill-name` が含まれている。
- ユーザーが求めていないプロジェクト固有名を汎用ルールとして固定していない。
- references/ 内の相対リンク、画像参照、添付ファイル参照が解決できる。不要な外部URLと埋め込みが残っていない。
- 参照資料に、ユーザーの依頼範囲外のインストール手順、GUI操作、個人環境の設定が残っていない。
- テンプレートリポジトリで新しい再利用Skillを追加した場合は、選択質問、コピー処理、予約名一覧、利用可能Skill一覧も更新されている。
- 検証スクリプトが使える環境では実行する。依存関係不足などで実行できない場合は、その理由を報告する。
